# Job document import and position count

The redesigned frontend job form supports PDF and Word `.docx` uploads up to 4 MB. Older `.doc` files must be saved as `.docx`. Choose **Fill fields** to send extracted text to the configured AI provider, fill empty fields, and review before **Save draft**. Existing entries are preserved. Missing or ambiguous values remain for manual entry. The original extracted text supplies the description if it is empty.

The form has dropdowns for Job type (Full-Time, Contract, Free-lancing), Work mode (Work from Home, Hybrid, Work from Office), Experience required (0–50 whole years, blank when unspecified), and Currency (common codes including INR/USD/EUR/GBP). Existing or imported currencies outside the common list remain selectable. The Logo control has been removed; editing an existing job preserves its stored logo. Experience is saved in `job_details.experience_years`, appears in role details and requires no database migration. Document import normalizes supported job/work-mode aliases and extracts an explicit minimum whole-year experience requirement; unsupported or ambiguous values are left for review.

`POST /api/v1/rms/job-document` accepts multipart `file` and `allow_provider_processing=true`. It requires an active admin, recruiter or manager with RMS access. The existing `AI_RECRUITER_TOOLS_ENABLED` switch and shared AI provider/model configuration apply. PDF/DOCX extraction uses the existing AI dependencies. Uploads are not stored and this endpoint creates no job, position or application. Encrypted, unreadable, oversized and overlong documents return validation errors. PDF extraction supports up to 30 pages and the existing local OCR fallback; OCR requires its existing runtime support.

The form replaces separate position setup with **Number of positions** (1–100; existing/imported larger valid counts remain selectable). Saving a new requisition without `position_id` creates a job-specific position and, if needed, its department within the same transaction. Its capacity equals `job_details.no_of_openings`. A manager's generated position is assigned to that manager. Separate-person HR/admin approval and publication rules are unchanged.

Existing clients can still send a scoped `position_id`; their capacity and manager restrictions remain. The server records whether the position was job-created in the immutable requisition creation audit event. Only that job-created position can be resized from its draft, and only while unoccupied and not shared with another requisition. If the audit evidence is unavailable, resizing fails closed through the normal capacity check. No schema migration is required.

Verification uses synthetic PDFs/DOCX and mocked AI responses in `tests/test_job_document.py`. Frontend `scripts/preview-job-import.cjs` and `scripts/check-job-import.cjs` verify field filling, preserving entries, failed-upload recovery, saved request payload and desktop/mobile layout using an isolated fixture. These checks do not certify live provider extraction quality or an authenticated production workflow.
